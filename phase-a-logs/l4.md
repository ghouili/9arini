## Migrations (written here BEFORE applying)

### 0029_content_moderation.sql — step 1 (A26), written before `npm run db:sql`

```sql
BEGIN;
ALTER TABLE "tutors" ADD COLUMN IF NOT EXISTS "pending_full_name" text;
COMMIT;
```

Why: a verified tutor's rename must wait for review while the tutor stays public
under the approved name. `tutors.full_name` keeps being the one public name every
surface reads; the requested name waits in `pending_full_name`.

How existing rows are kept: the column is nullable with no default and no backfill,
so `ALTER TABLE … ADD COLUMN` rewrites nothing; every existing tutor reads as "no
rename pending" (NULL). No other column, constraint or row is touched.
Rollback: `ALTER TABLE "tutors" DROP COLUMN IF EXISTS "pending_full_name";`
(loses only renames still waiting for review).

### 0029_content_moderation.sql — step 2 (A28), written before `npm run db:sql`

```sql
ALTER TABLE "messages" ADD COLUMN IF NOT EXISTS "hidden_at" timestamp with time zone;
ALTER TABLE "messages" ADD COLUMN IF NOT EXISTS "hidden_by" uuid;
ALTER TABLE "messages" ADD COLUMN IF NOT EXISTS "hidden_reason" text;
ALTER TABLE "reviews"  ADD COLUMN IF NOT EXISTS "hidden_at" timestamp with time zone;
ALTER TABLE "reviews"  ADD COLUMN IF NOT EXISTS "hidden_by" uuid;
ALTER TABLE "reviews"  ADD COLUMN IF NOT EXISTS "hidden_reason" text;
-- hidden_by → profiles(id) ON DELETE SET NULL, one DO block per table (duplicate_object → no-op)
```

Why: a soft delete. The text stays in `body` / `text` as evidence (admins read it);
`hidden_at` says it is hidden, `hidden_by` which admin, `hidden_reason` why (the
reason stays on the row, not in the audit note — audit.ts: "say what was done, not
what it contained").

How existing rows are kept: six nullable columns with no default and no backfill —
no row is rewritten, every existing message and review reads as NOT hidden (NULL
hidden_at), so every surface shows exactly what it showed before. The FKs are
`ON DELETE SET NULL`, so erasing an admin's profile can never delete or block a
message/review. Same file as step 1 (idempotent, re-applied whole by db:sql).
Rollback: `ALTER TABLE "messages" DROP COLUMN IF EXISTS "hidden_at", DROP COLUMN IF
EXISTS "hidden_by", DROP COLUMN IF EXISTS "hidden_reason";` and the same on
"reviews" (hidden content becomes visible again).

`schema.ts` matches column for column (`tutors.pendingFullName`, `messages.hiddenAt/hiddenBy/
hiddenReason`, `reviews.hiddenAt/hiddenBy/hiddenReason`, each in a `// phase-a lane L4` block).
