## Migrations (written here BEFORE being applied)

### `0027_consent_phone_optional.sql` — A18.2

```sql
BEGIN;
ALTER TABLE "consents" ALTER COLUMN "guardian_phone" DROP NOT NULL;
COMMIT;
```

**How existing rows are kept:** untouched. No row is updated or deleted; every
guardian phone already on file stays as it is. The statement only relaxes the
NOT NULL constraint so a consent given WITHOUT a phone stores NULL ("not
collected") instead of an invented placeholder. Idempotent (DROP NOT NULL on a
nullable column is a no-op). Rollback (manual): fill NULLs with `''`, then
`SET NOT NULL`.

Why a migration at all: the spec says "the column stays nullable", but
`guardian_phone` was created `NOT NULL` (0000_init.sql:126). Making the phone
optional without inventing a value needs the constraint relaxed. The file uses my
reserved number 0027 with a distinct suffix (`0027_consent_…` sorts before
`0027_levels.sql`), so it cannot collide with another lane.

### `0027_levels.sql` — A18.7

```sql
BEGIN;
DO $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns
                 WHERE table_schema='public' AND table_name='tutors' AND column_name='levels') THEN
    ALTER TABLE "tutors" ADD COLUMN IF NOT EXISTS "levels" text[] NOT NULL DEFAULT '{}'::text[];
    UPDATE "tutors" t SET "levels" = ARRAY[m.code]
      FROM (VALUES ('primaire','primaire'), ('ابتدائي','primaire'),
                   ('collège','college'), ('college','college'), ('إعدادي','college'), ('اعدادي','college'),
                   ('secondaire','secondaire'), ('lycée','secondaire'), ('lycee','secondaire'), ('ثانوي','secondaire'),
                   ('bac','bac'), ('baccalauréat','bac'), ('باك','bac'), ('باكالوريا','bac'),
                   ('université','universite'), ('universite','universite'), ('supérieur','universite'),
                   ('superieur','universite'), ('جامعة','universite'), ('جامعي','universite')) AS m(label, code)
     WHERE lower(btrim(t."level")) = m.label
       AND t."level" <> 'Bac';  -- the old column DEFAULT: never a tutor's choice
  END IF;
END $$;
ALTER TABLE "classes" ADD COLUMN IF NOT EXISTS "level" text;
ALTER TABLE "tutors" ALTER COLUMN "level" DROP DEFAULT;
COMMIT;
```

**How existing rows are kept:**
- Nothing is dropped or overwritten: `tutors.level` keeps every value (never
  dropped, per the lane note); tables only gain columns.
- `tutors.levels` is backfilled from `tutors.level` only where the value maps
  cleanly to one code; otherwise it stays `{}`.
- **Deliberate exception — the exact string `'Bac'`.** It is the column's old
  DEFAULT; no code path ever wrote `tutors.level` (verified: `grep level
  apps/api/src` — only reads), so `'Bac'` never expressed a tutor's choice.
  Copying it would re-create the bug A18.7 fixes ("every tutor labelled Bac").
  Those tutors keep `level='Bac'` untouched and get no levels until they choose.
  (A deliberately typed lowercase `bac` or `باك` would still map.) If the founder
  prefers to map `'Bac'` too, it is one line: remove the `AND t."level" <> 'Bac'`.
- The backfill runs once (inside the block that creates the column), so a later
  `npm run db:sql` never refills levels a tutor has since cleared.
- `DROP DEFAULT` on `tutors.level` only affects rows inserted from now on.

Rollback (manual): drop `tutors.levels`, drop `classes.level`, `SET DEFAULT 'Bac'`.

```sql
    ('histoire-geographie','histoire-geo'), ('histoire','histoire-geo'),
    ('تاريخ وجغرافيا','histoire-geo'), ('تاريخ-جغرافيا','histoire-geo'), ('تاريخ و جغرافيا','histoire-geo'),
    ('philosophie','philosophie'), ('philo','philosophie'), ('فلسفة','philosophie'), ('الفلسفة','philosophie'),

    ('technique','technique'), ('تقني','technique'), ('تقنية','technique')),
exploded AS (SELECT p.id, t.ord, btrim(t.val) AS val
               FROM profiles p, unnest(string_to_array(p.subjects, ',')) WITH ORDINALITY AS t(val, ord)
              WHERE p.subjects IS NOT NULL AND p.subjects <> ''),
mapped AS (SELECT e.id, e.ord, COALESCE(m.code, e.val) AS v
             FROM exploded e LEFT JOIN map m ON m.label = lower(e.val) OR m.label = e.val

dedup AS (SELECT id, v, min(ord) AS ord FROM mapped GROUP BY id, v),
joined AS (SELECT id, string_agg(v, ',' ORDER BY ord) AS s FROM dedup GROUP BY id)

```

**How existing rows are kept:** only `profiles.subjects` values change, and only
entries that are a known FR/AR label: each becomes its code, in the same order;
the same subject written in both languages collapses to one code. **Any entry
that maps to no code is kept exactly as typed (trimmed) — never dropped**; the
display falls back to the raw value. NULL / `''` rows are untouched; no column
is added or removed. Idempotent (a code maps to itself; the UPDATE skips
unchanged rows). No lossless rollback exists (two labels → one code); the header
gives the inverse mapping approach. The listing query for unmapped values is in
the file header; its result on this lane's DB is recorded under A18.12 below.

`tutors.subject` is NOT converted: it is the tutor's free-text headline ("Prof de
Maths · Lycée & Bac"), not a list of tags — see A18.12 notes.
